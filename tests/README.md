# Интеграционные тесты чата

Покрытие корректности дат, с которыми чат оперирует — на каждом шаге flow записи.

## Структура

- **`cycle1-booking.ts`** — полный сценарий «запиши к терапевту»: запрос → выбор слота → ввод данных пациента → подтверждение → создана запись. Проверяются даты на каждом шаге.
- **`cycle2-availability.ts`** — лёгкий цикл «есть ли окно у терапевта»: одна реплика, проверка ответа.
- **`lib.ts`** — общие хелперы (HTTP-клиент, date-helpers, ассерты, мини-раннер).

## Что проверяется

### Дни недели
Понедельник… Воскресенье — ближайшая дата ожидаемого дня. Воскресенье — негативный кейс (терапевты не работают).

### Описательные выражения
- «ближайшее время»
- «на следующей неделе»
- «через неделю»
- «в начале недели», «в конце недели»

### Месяцы
- «в начале следующего месяца»
- «на следующий месяц»
- «через месяц»

### День + время суток
- «в понедельник в утреннее время» → дата = Пн, время 09:00–12:00
- «во вторник вечернее время» → дата = Вт, время 16:00–19:00

### Конкретное время и даты
- «в 11:00 в среду» → дата = Ср, в ответе фигурирует «11:00»
- Конкретные даты (today+7, начало след. месяца)

## Уровни проверок

- **HARD** — `slot.date` из результата tool-вызова (детерминированно).
- **SOFT** — текст ответа упоминает дату (в формате «25 мая» / «понедельник» / «2026-05-25»).
- **HARD** — для cycle 1: финальный `function:book_appointment` имеет `success=true`.

## Запуск

Требуется:
- Backend на `http://localhost:3000` (или задать `CHAT_API`)
- MedFlex-мок на `http://localhost:3001`
- БД (PostgreSQL) с настроенной `clinicNet` id=1 и `medflexKey`

```sh
cd tests
npm install

# Очистить appointments.json в моке (cycle 1 создаёт реальные записи)
npm run reset

# Запустить
npm run test            # оба цикла
npm run test:cycle1     # только cycle 1 (полная запись)
npm run test:cycle2     # только cycle 2 (проверка ответа)
```

Фильтр по подстроке имени теста:

```sh
npm run test:cycle1 -- 'понедельник'   # запустит только тесты с "понедельник" в названии
npm run test:cycle2 -- 'месяц'         # все тесты про месяцы
```

## Сброс состояния

После запуска cycle1 в `medflex-mock/data/appointments.json` останутся тестовые записи. Перед повторным запуском:

```sh
npm run reset
```

Хук `resetMock()` в `cycle1-booking.ts` вызывается автоматически при старте.

## Стоимость

- **Cycle 1**: 4 LLM-вызова на тест × 19 тестов = ~76 вызовов
- **Cycle 2**: 1 LLM-вызов на тест × 20 тестов = ~20 вызовов

Итого ~100 вызовов GigaChat на полный прогон. Используйте фильтр для частичных прогонов.

## Тонкости

- Тесты НЕ детерминированы на 100% (LLM может варьировать формулировки). Хард-проверки (`slot.date`, `book_appointment.success`) надёжнее, чем софт-проверки по тексту.
- Сегодняшняя дата берётся из `new Date()` (системные часы машины). Бэкенд тоже использует `new Date()` — должны совпадать.
- Для воскресенья тесты ожидают ответ «нет слотов», т.к. в моке терапевты Иванова (Пн/Ср/Пт) и Петров (Вт/Чт/Сб) по воскресеньям не работают.
- Сценарий полной записи использует гостевой режим (`misType: 'medflex'`, без `encryptedPatient`). Данные подставляются строкой `Тестов Тест Тестович, 79991234567, 1 января 1990`.
