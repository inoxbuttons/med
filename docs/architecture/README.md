# Архитектура ИИ-ассистента записи: анализ и рефакторинг

1. [Текущее состояние](01-current-state.md): как устроен ход диалога, откуда берутся входные токены (замеры) и почему систему трудно расширять.
2. [Целевая архитектура](02-target-architecture.md): жёсткий пайплайн, в котором модель только понимает реплику (NLU) и пишет свободный ответ. Поиск гибридный (FTS + trigram + pgvector). Промпты собираются из слоёв по клиникам, у каждой сети свой профиль, МИС подключаются через порты.
3. [План рефакторинга](03-refactoring-plan.md): 8 этапов с файлами, сроками и способами проверки, плюс открытые вопросы.
4. [Модель диалога](04-dialog-model.md): как код справляется с разнообразием запросов. Запрос раскладывается на цель и ограничения, резолвер закрывает недостающие требования, на вопросы отвечают отдельные обработчики, а редкие случаи уходят агенту как запасной путь.
